# Leon Blog UI 设计规范

> 版本：v0.2（2026-07-29 首页审查与实施基线版）  
> 依据：`01-产品需求文档-PRD.md`  
> 当前范围：信息架构、关键流程、三种视觉方向、可实施设计系统、首页桌面/移动基线  
> 已选方向：方向 1「温暖编辑型开发者日志」

## 0. 本轮审查结论与实施基线

审查对象：

- `design/ui-screens/01-首页-桌面端-v1.png`
- `design/ui-screens/02-首页-移动端-v1.png`

两张首页稿正确表达了开发者个人博客、长期写作和求职作品集定位，可以作为方向与布局基线；它们不是新增产品范围的依据，也暂不作为逐像素自动化基线。以下修正决定优先于 v1 图片中的可见细节，待后续首页 v2 设计时同步回写图片：

1. “关于我”不新增独立路由，首页次级行动改为“查看全部文章”，指向 `/posts`。
2. “实践项目”仅是首页的一条静态作品证据，不建立项目表、项目后台或 `/projects` 产品线；“查看项目”只能指向配置好的 GitHub 或在线演示外链。
3. 手机端主要分类由单行四项调整为 `2 × 2` 网格，避免在 390 px 宽度下压缩文字和触控区域。
4. `vermilion-600` 只用于按钮底色、图形和大字号强调；米白背景上的小字号链接、日期和状态文字使用对比度更高的 `vermilion-700`。
5. 手机端搜索和菜单按钮至少为 `44 × 44 px`。菜单采用页头下方展开的轻量导航区，不使用 SaaS 式侧栏。
6. 桌面 Hero 图片在手机端可以隐藏，但必须被定义为装饰图片；作品截图属于内容证据，不能省略，需提供有意义的 `alt`。

设计与实现的事实来源：

- PRD 决定页面和功能范围。
- 本文决定视觉 Token、布局、交互状态和组件外观。
- v1 图片用于说明气质和内容层级；本文明确的修正项优先。
- 技术架构决定组件边界、数据流、安全、缓存和部署。

## 1. 产品体验定位

Leon Blog 是开发者个人博客与求职作品集，不是企业 CMS、内容社区或 SaaS 后台。

设计目标：

- 让访客快速理解作者擅长什么，并低成本进入文章阅读。
- 通过文章、分类、标签和搜索形成清晰的内容发现路径。
- 用真实文章和首页作品证据体现工程能力，避免堆砌技术徽章。
- 管理端保持轻量，服务单一管理员的创作、预览、发布和维护。
- 优先保证阅读体验、响应式、可访问性和状态反馈。

明确不设计：

- 多用户、角色权限和审核流。
- 评论、点赞、收藏和社交关系。
- 数据大屏、复杂统计和企业工作台。
- 独立项目详情产品线；作品能力仅作为首页证据区呈现。
- 为视觉展示增加新的数据库实体、管理入口或 API。

## 2. 页面信息架构

### 2.1 访客端

```text
首页 /
├── 作者定位与简介
├── 最新文章
├── 主要分类
└── 作品能力证据（首页区块，不新增独立路由）

文章 /posts
├── 文章列表
├── 分页
└── 文章详情 /posts/[slug]
    ├── 标题、摘要、日期、分类、标签
    ├── Markdown 正文与代码块
    ├── 文章目录（P1）
    └── 相关文章（P1）

分类 /categories
└── 分类文章 /categories/[slug]
标签 /tags
└── 标签文章 /tags/[slug]
搜索 /search?q=
系统状态 /404、空结果、错误页
```

全局导航固定为：文章、分类、标签、搜索。作者介绍和作品证据位于首页，不在 P0 增加独立页面。

导航行为：

- 桌面端直接显示四个入口：文章进入 `/posts`，分类进入 `/categories`，标签进入 `/tags`，搜索进入 `/search`；当前路由同时使用文字语义和下划线表示，不只依赖颜色。
- 手机端保留搜索按钮与菜单按钮；菜单按钮展开文章、分类和标签三个入口，搜索按钮直接进入 `/search`。
- 展开菜单使用 `aria-expanded`、`aria-controls`，支持 `Esc` 关闭并把焦点还给菜单按钮。
- 首页“阅读最新文章”进入当前最新已发布文章；没有已发布文章时改为“浏览文章”并进入 `/posts` 空状态。
- 首页次级行动固定为“查看全部文章”并进入 `/posts`，不新增“关于我”页面。
- 作品证据链接只允许站点配置中的 GitHub 或 HTTPS 演示地址，并清楚标注为外部链接。

### 2.2 管理端

```text
登录 /admin/login
管理入口 /admin
├── 文章列表 /admin/posts
├── 新建文章 /admin/posts/new
├── 编辑文章 /admin/posts/[id]/edit
├── 文章预览 /admin/posts/[id]/preview
├── 分类管理 /admin/categories
└── 标签管理 /admin/tags
```

文章编辑核心字段：标题、摘要、Markdown 正文、分类、标签、slug、SEO 标题、SEO 描述、分享图片 URL。

## 3. 关键流程

### 3.1 访客发现与阅读

```text
首页
→ 最新文章或主要分类
→ 文章列表
→ 文章详情
→ 同分类或同标签文章
```

```text
搜索引擎或分享链接
→ 文章详情
→ 阅读正文与代码
→ 分类或标签
→ 继续阅读
```

```text
站内搜索
→ 输入标题或摘要关键词
→ 搜索结果
→ 文章详情
```

### 3.2 管理员发布

```text
登录
→ 文章列表
→ 新建草稿
→ 编辑内容与元数据
→ 保存草稿
→ 预览
→ 发布
→ 公开文章页
```

### 3.3 更新与归档

```text
文章列表
→ 编辑已发布文章
→ 保存更新
→ 刷新公开内容
```

```text
文章列表
→ 归档
→ 从公开列表和搜索中移除
→ 原地址返回 404（P1 可配置重定向）
```

## 4. 三种视觉方向

### 方向 1：温暖编辑型开发者日志（已选）

- 米白纸张背景、墨黑正文、朱红强调色。
- 中文衬线标题搭配清晰的无衬线正文。
- 强调阅读、思考和长期主义，技术感来自内容结构而非炫酷装饰。
- 最符合个人博客、求职作品集和长期写作定位。

### 方向 2：现代系统作品集

- 亮白背景、深色文字、电蓝强调。
- 大字号无衬线排版和产品截图证据。
- 求职展示更直接，但容易接近产品官网或 SaaS 落地页。

### 方向 3：终端夜间工作台

- 深色背景、青色和酸绿强调。
- 等宽信息、终端语义和高技术密度。
- 个性鲜明，但长文阅读压力更高，不适合作为默认主题；可作为未来深色主题的参考。

## 5. 颜色体系

### 5.1 基础色

| Token | 色值 | 用途 |
|---|---|---|
| `paper-50` | `#F7F4EE` | 页面主背景 |
| `surface-0` | `#FFFFFF` | 局部内容底色 |
| `ink-900` | `#171717` | 标题和正文 |
| `stone-700` | `#6F6A61` | 次要文字 |
| `stone-300` | `#D7D1C7` | 分割线和边框 |
| `vermilion-600` | `#C34A32` | 主操作、当前状态和链接强调 |
| `vermilion-700` | `#A93B27` | 悬停和按下状态 |
| `success-700` | `#356449` | 成功文字与图标 |
| `warning-700` | `#7A5716` | 警告文字与图标 |
| `danger-700` | `#9E2F26` | 错误文字与图标 |

### 5.2 语义规则

- 正文和小字号文本与背景对比度至少达到 `4.5:1`；大字号文本至少达到 `3:1`。
- `vermilion-600` 与 `paper-50` 的对比度不足以承载普通小字，因此只用于白字按钮底色、图形、短线和大字号强调。
- 米白背景上的普通链接、日期和状态文字固定使用 `vermilion-700`；链接还需具备下划线、箭头或明确文案。
- 朱红只用于关键操作、选中状态和少量视觉节奏，不用于大面积背景。
- 状态不能只依赖颜色；错误、成功和当前项同时使用文字或图标说明。
- `Focus Visible`、`Pressed`、`Selected / Current`、`Disabled` 和 `Error` 是独立状态，不得共用一个状态类混合表达。
- 常规浅色主题下使用分型焦点指示：输入控件改变内部背景，操作和表面控件使用内描边，文字与导航链接使用下划线和字重。已分型控件不显示黑色外轮廓。
- 未分类的原生低频控件使用 `2 px` 品牌色可见焦点作为安全回退，不得以透明或零宽 `outline` 隐藏焦点。
- 强制颜色模式保留操作系统的可见焦点轮廓；不硬编码系统最终显示的 RGB 色值。
- P0 只实现浅色主题，但组件只能使用语义变量，不直接散落十六进制色值。

建议映射为 CSS 语义变量：

| 变量 | 浅色值 |
|---|---|
| `--color-bg` | `paper-50` |
| `--color-surface` | `surface-0` |
| `--color-text` | `ink-900` |
| `--color-text-muted` | `stone-700` |
| `--color-border` | `stone-300` |
| `--color-accent` | `vermilion-600` |
| `--color-accent-text` | `vermilion-700` |
| `--color-focus-surface` | `#F7E6E2` |
| `--color-focus-accent` | `vermilion-700 / #A93B27` |
| `--color-focus-on-accent` | `surface-0 / #FFFFFF` |
| `--focus-indicator-width` | `2px` |
| `--focus-underline-thickness` | `2px` |
| `--color-success` | `success-700` |
| `--color-warning` | `warning-700` |
| `--color-danger` | `danger-700` |

P1 深色主题使用同一组语义变量，不改变组件 API：

| 变量 | 深色值 |
|---|---|
| `--color-bg` | `#171612` |
| `--color-surface` | `#211F1A` |
| `--color-text` | `#F2EDE3` |
| `--color-text-muted` | `#B9B0A3` |
| `--color-border` | `#49433A` |
| `--color-accent` | `#D96B50` |
| `--color-accent-text` | `#F08A70` |

本轮不实现深色主题的焦点值；未来启用深色主题时，必须为同一组焦点语义 Token 重新验证明度、对比度和强制颜色模式，不复用旧的单一外轮廓变量。

## 6. 字体体系

P0 不下载体积较大的中文 Web Font，使用系统字体栈，避免字体请求、许可和中文大字库影响首屏性能：

- 展示标题：`"Songti SC", "STSong", "Noto Serif SC", "Source Han Serif SC", serif`，Bold。
- 正文与界面：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", "Source Han Sans SC", system-ui, sans-serif`，Regular / Medium。
- 代码：`"SFMono-Regular", Consolas, "Liberation Mono", monospace`。

如果 P1 需要跨平台完全一致的品牌字体，只能使用有明确 Web 授权的 WOFF2 子集，并通过 `next/font/local` 自托管；引入前需要重新验证字体体积、中文覆盖和 CLS，不同时保留第三方运行时字体请求。

| 样式 | 桌面 | 移动 | 行高 |
|---|---:|---:|---:|
| Hero | 56–64 px | 38–44 px | 1.18 |
| H1 | 40 px | 32 px | 1.3 |
| H2 | 28 px | 24 px | 1.4 |
| H3 | 22 px | 20 px | 1.45 |
| 正文 | 17–18 px | 16 px | 1.8 |
| 元信息 | 13–14 px | 13 px | 1.6 |

文章正文单行宽度控制在 680–720 px，避免桌面端长行阅读。

## 7. 间距与布局

基础间距：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96`。

- 全站内容最大宽度固定为 `1248 px`。
- 桌面页边距固定为 `64 px`，超宽屏由居中容器吸收额外空间。
- 平板页边距固定为 `32 px`。
- 手机页边距固定为 `20 px`。
- 文章阅读正文最大宽度固定为 `720 px`。
- 列表与正文的最小垂直节奏以 `24 px` 为单位，主要区块间距使用 `64 / 80 px`。
- 圆角：以 0、4、8 px 为主，避免 SaaS 式大圆角卡片。
- 阴影：默认不用；仅在浮层或必要的层级关系中使用轻阴影。

响应式断点固定为 Tailwind 的移动优先 `md` / `lg`：

- Mobile：默认样式，`< 768 px`
- Tablet：`md`，`>= 768 px`
- Desktop：`lg`，`>= 1024 px`

布局规则：

- Hero 在 `< 1024 px` 时改为单列；桌面 Hero 图片可在 `< 768 px` 隐藏。
- 首页“最新文章 / 实践项目”桌面为主次双栏，`< 1024 px` 按最新文章、实践项目顺序堆叠。
- 手机端主要分类使用两列网格；不得通过缩小到 13 px 以下来维持单行。
- 代码块和宽表格允许容器内横向滚动，页面本身不得产生横向滚动。
- 文字放大到 200% 时，导航、按钮和正文不能重叠或截断。

## 8. 基础组件体系

### 8.1 访客端

- `SiteHeader`：站点名、文章、分类、标签、搜索。
- `MobileNavDisclosure`：唯一必要的 P0 访客端交互岛；只管理手机菜单展开、关闭和焦点恢复。
- `HomeHero`：作者定位、说明和两个文章入口；Hero 视觉不承载唯一信息。
- `TopicGrid`：主要分类或技术方向入口；手机两列、桌面横向排列。
- `PrimaryButton`：主要操作。
- `TextLink`：次要操作和文章跳转。
- `SearchField`：搜索输入、清除、提交和无结果状态。
- `ArticleRow / ArticleCard`：标题、摘要、日期、分类和阅读入口。
- `ArticleMeta`：发布日期、分类、标签。
- `CategoryLink`：分类入口。
- `Tag`：文章标签。
- `ProjectEvidence`：首页单条静态作品证据，包含名称、问题、职责/结果摘要、优化截图和一个外链；不读取业务数据库。
- `Pagination`：上一页、页码、下一页。
- `MarkdownContent`：正文排版。
- `CodeBlock`：语言标识、服务端语法高亮和横向滚动。
- `EmptyState / ErrorState / LoadingState`：统一状态反馈。

### 8.2 管理端

- `AdminHeader`：当前位置和退出。
- `PostStatus`：草稿、已发布、已归档。
- `PostTable`：文章列表和核心操作。
- `MarkdownEditor`：编辑与预览模式。
- `FormField`：标题、摘要、slug 和 SEO 字段。
- `TaxonomyPicker`：分类单选和标签多选。
- `ConfirmDialog`：删除、归档等不可逆操作确认。
- `SaveBar`：保存草稿、预览和发布。

### 8.3 必备状态

按钮、链接、输入框和筛选项至少包含：

- Default
- Hover
- Pressed
- Focus Visible
- Selected / Current（适用于导航、筛选、页码和选择控件）
- Disabled
- Loading（适用于提交操作）
- Error（适用于输入）

所有可交互控件应支持键盘操作，并提供清晰的焦点样式。指针按下的瞬时反馈不能代替键盘焦点，当前项在焦点离开后仍须保留持久状态。

组件外观与交互规则：

- 按钮最小高度 `44 px`；纯图标按钮最小 `44 × 44 px`，必须有可访问名称。
- 主要按钮使用 `vermilion-600` 底色和白字；Hover/Pressed 使用 `vermilion-700`，Loading 时保留原宽度。
- 主要按钮获得键盘焦点时使用更深品牌背景和 `2 px` 反白内描边；次要按钮使用浅暖背景和 `2 px` 品牌内描边；危险按钮保留危险色语义和反白或危险色内描边。
- 图标按钮、卡片链接、标签、筛选和分页获得焦点时使用浅暖背景和 `2 px` 品牌内描边。内描边不参与盒模型，不得引起尺寸或布局变化。
- 文本链接默认使用正文色和下划线；重点链接可用 `vermilion-700`，不能只靠颜色表达可点击。
- 文字和导航链接获得键盘焦点时使用 `2 px` 下划线、更大的下划线间距和一级字重提升，不显示黑色外框。导航当前项使用 `aria-current="page"` 和独立的持久视觉状态。
- 访客端文章以分隔线列表为主，不使用带阴影的大圆角卡片。
- 输入框高 `44 px` 起，Label 永远可见；Placeholder 不替代 Label。
- 文本输入、搜索、密码、文本域和选择控件获得输入焦点时，保留原 `1 px` 语义边框并把内部背景切换为 `--color-focus-surface`；不显示外部 `outline`、ring 或阴影。失焦后恢复默认表面。
- `aria-invalid="true"` 的错误边框、错误文案和 `aria-describedby` 关联的优先级高于焦点背景；Disabled 和 readonly 控件不显示可编辑焦点状态。
- 加载 Skeleton 只模拟当前区域结构，遵循 `prefers-reduced-motion`；服务端错误提供重试或返回入口。

### 8.4 Markdown 内容规范

- 正文容器最大宽度 `720 px`，桌面正文 `18 px / 1.8`，移动正文 `16 px / 1.8`。
- `H2` 前间距 `48 px`、后间距 `16 px`；`H3` 前间距 `32 px`、后间距 `12 px`。
- 正文链接使用 `vermilion-700` 与下划线；外链明确可识别。
- 引用使用左侧 `3 px` 朱红线和 `24 px` 内边距，不使用大面积灰色卡片。
- 图片保留宽高比、限制在正文宽度内，并显示说明文字；不得造成 CLS。
- 表格放入可横向滚动容器，表头使用语义 `<th>`。
- 代码块使用深墨色背景、浅色代码和语言标识；移动端横向滚动，不缩小代码字号。
- 原始 HTML、危险协议和未知图片主机的处理服从技术架构，不由 CSS 或客户端脚本补救。

## 9. 首页方向 1 的内容结构

```text
全局导航
→ 作者定位 Hero
→ 最新文章主入口
→ 主要分类
```

首页首屏的核心信息：

- 作者是谁。
- 关注什么技术和问题。
- 最值得阅读的文章入口。
- 一项能够证明工程能力的作品或实践证据。

作品区只提供必要的项目名称、问题、职责、技术范围和结果摘要，不扩展为企业案例库。

首页实现内容：

- Hero 主行动：“阅读最新文章”；无文章时回退为“浏览文章”。
- Hero 次行动：“查看全部文章”；固定进入 `/posts`。
- 主要分类来自公开分类查询；技术方向图标为装饰，分类名称本身必须可读。
- 最新文章区只展示已发布文章；首篇可显示摘要，其余条目保持高密度可扫描。
- 实践项目来自站点静态配置，不进入 Prisma、Repository、管理 API 或管理后台。
- 桌面端 Hero 图片为装饰图片并使用空 `alt`；移动端可隐藏。
- 作品截图必须使用真实、经过裁切的项目界面证据和有意义的 `alt`，不能用空白占位。
