# ops/ — 真实部署事实登记

本目录固化 leon-blog 的生产部署事实契约：**部署完成后必须留下可核验的记录**。
部署执行本身（如何把 Next.js 发到生产）属于项目运维既有流程，不在本契约范围内。

## 文件

| 文件 | 作用 |
|---|---|
| `deployment-records.yaml` | 当事人申报侧登记文件（当前为空：`records: []`） |
| `evidence/` | 控制台截图/导出物等证据存档（登记时创建，大文件可另行取舍，但须保留清单） |

## 登记流程（部署完成后由维护人执行）

1. 从部署平台或生产环境读取**实际生效 SHA**、部署 ID、生效时间。
2. 将证据存档到 `ops/evidence/`（截图/导出物），或确认可走平台 API 回查。
3. 在 `deployment-records.yaml` 追加一条记录，`evidence_source.kind` 按实际证据形态选择。
4. 提交本目录变更（由仓库维护流程决定提交时机；本契约不代用户提交）。

核验（`claimed → evidence_pending → verified | rejected`）由 leon_knowledge 的
kb-sync 在受信任侧执行；本文件是申报，**不能自证上线**。只有核验态 `verified`
记录的 `effective_sha` 才能被当作目标环境的上线事实。

## 证据来源分级

| kind | 含义 | 核验要求 |
|---|---|---|
| `platform_api` | 平台 API / 签名回调可程序化读取 | 可信服务端用受限凭据回查部署 ID，核对环境、状态成功、生效 SHA 与时间；回调须校验签名与重放 |
| `platform_console_artifact` | 控制台截图 / 导出（人工取证） | 证据存档于 `ops/evidence/`；经身份验证的维护人核对并留下独立确认记录。只填截图路径不算核验，找不到原件保持 `evidence_pending` |
| `manual_verified` | 维护人亲眼核验生产环境后登记 | 必须从生产环境或部署平台读取生效版本，记录查询方式、证据摘要、核验身份与时间。只检查 SHA 是否在 Git 中不够 |
| `simulated` | 本地模拟（测试 fixture 专用） | **拒入真实台账**（核验侧 rejected） |

## 硬性约束

- **tag 不是上线证明**：打 tag、合并 master、CI 绿都只描述代码候选，均不构成生产生效证据。
- **平台未知 = 状态 unknown**：本仓库当前无法确定真实部署平台（无 Dockerfile /
  vercel.json / standalone 配置）。在查明并取得可信证据之前，生产部署状态保持
  `unknown`，本文件保持空 `records`，不得填入占位 SHA 冒充上线事实。
- **旧部署被取代**：新部署生效后，尚未核实的新变更不得继续被称为当前线上事实；
  未受影响对象可继续服务，但须标注快照版本与核验时间。
- **隐私**：证据与备注中不得包含密码、cookie、JWT、数据库连接串或其他凭据；
  截图入库存档前应确认无环境敏感信息。
